# 夜1回の現物株・50万円運用（仮想売買の実装方針）

## ユーザー確定方針（2026-10-09）
- 判断は**夜に1回だけ**。日中は監視・売買判断を行わない。
- **買ってから売る**。現物のみ。先物、空売り、信用売買、レバレッジ、借金を使う取引、保有株数を超える売却は禁止。
- 運用に使用する余裕資金の基準額は **500,000円**。収益を再投資する際も必ず手元現金の範囲内に制限。
- 現段階は**仮想売買の検証と注文候補の表示のみ**。証券会社への自動発注は厳禁。
- 翌営業日の始値で仮約定させる履歴バックテスト。夜に作る翌営業日注文候補は未約定であり、実際の成行価格は保証されない。
- 注文を出す前に、最新価格の日付、100株単位、残余現金、保有数量、手数料、株式分割と約定可否を点検。

## 今回の実装
- `walkforward_backtest.py` 初期資金を500,000円に更新。現物買いと保有売却のみ、売り注文を先に約定させ、残現金から買付。ポジション数量が常に正、現金残高が負にならないことを実行時に検査。
- `nightly_paper_plan.py` 端末にある日足と**非公開口座状態JSON**から、その晩の次営業日向け**仮想注文候補**を生成。買いは資金残高と単位株の範囲内、売りはJSONで保有している銘柄の保有株数以内。
- 元株価が7日超古いと `stale=true` として注文候補をゼロ件にする（未来の日付も遮断）。無料J-Quantsの12週間遅延では常に実取引向け注文候補を出せない。最近の相場データを無料かつ適法に取得できるまではこの制限を解除しない。
- `tests/test_nightly_paper_plan.py`: 古いデータ、未保有株の売却禁止、現金超過禁止、仮想売買整合性を検証。GitHub Actions `test-walkforward.yml` 成功。
- `nightly_paper_plan.py` は手動／CIで実行できる実装段階。**毎晩のスケジュール配信・口座保有株数の自動取得は未接続**。このため夜1回の実運用注文を自動送信することはない。

## 入出力例（機密ファイルは公開GitHubに登録しない）
```json
{"cash":500000,"holdings":{}}
```
```sh
python nightly_paper_plan.py --root archive/daily --account my-private-account.json --out nightly-paper-plan.json
python walkforward_backtest.py --root archive/daily --initial-cash 500000 --out backtest-results.json
```
出力JSONにはデータ基準日・鮮度・注文候補・理由・保有状態等を記録する。公開リポジトリやActionsログに個人の実保有・私用株価データを上げない。

## まだ必要な作業
- 実際の買い・売りルール（利益確定・損切り・保有期間・予算配分）を複数比較して探索。現コードはサンプルの期間リターンと出来高のルール、および保有日数による売却のみ。
- 利用許諾のある最新データを確保するか、最新情報はユーザーが証券会社画面で個別確認する方式を設計。
- 手数料・売買税金・スリッページ・値幅制限・注文不成立・流動性・企業アクションに対応して資金曲線の信頼性を改善。
- 実口座取引は自動化せず、ユーザー自身の明示確認が必要。
