# パターン別「1～30営業日後」の騰落統計データベース

## 目的
過去チャートについて「こういう形だったら、1・2・3・...・30営業日後に株価は何％の割合で上昇/下落したか」を一覧化する。**これは過去の件数割合であって、予測確率や実際に買った場合の利益ではない。**

- 日数は暦日でなく、東証で観測された**取引営業日**。20～22営業日がおおむね1か月、30営業日はおおむね6週間。
- パターンを判定する基準は **当日引け時点** の調整後終値・出来高まで。その後の価格をパターン判定に使うことは禁止。
- 1営業日後の騰落は `(翌営業日の調整後終値 / 基準日の調整後終値 - 1) * 100`。同じ基準日から2～30営業日後も計算する。
- 「1営業日目に上がった」から次の日に上がると推論するのではない。**毎列は基準日とその日を直接比較**。
- 複数パターンが同じ銘柄・同じ日に成立するのは許容。パターン相互の標本独立性は保証しない。
- 同一銘柄・同じパターンが連日出ても、**次の採用例まで30営業日空ける**。これは1営業日ごとに誤って独立例を増やさないため。
- 明示的に「上昇・下落・変化なし・未来の株価欠損・検証期間の未来（未成熟）」を別管理。上場廃止/売買停止後の株価を0や直近値で穴埋めしない。
- JPX上場注意情報は時点で公表済みと確認できた一部だけを除外。**全市場警告カバレッジは未完成**。企業行動・株式分割の履歴は照合未完了。結果の状態は `PROVISIONAL_CORPORATE_ACTIONS_UNVERIFIED`。

## 初期16パターン

| コード | 形状/条件 |
|---|---|
| BASE | 比較用、十分な履歴のある売買実績銘柄 |
| UP3 / DOWN3 | 3営業日連続上昇/下落 |
| UP5 / DOWN5 | 5営業日連続上昇/下落 |
| GAIN5 / LOSS5 | 5営業日で5%以上上昇/下落 |
| DIP_REV | 5日下落して当日反発 |
| RALLY_DIP | 5日上昇して当日反落 |
| HIGH20 / LOW20 | 20日終値の最高値突破/最安値割れ |
| SMA_BULL / SMA_BEAR | 短期（5日）平均が中期（20日）平均より上/下 |
| SIDEWAYS | 20日の終値レンジが6%以内 |
| VOL_UP / VOL_DOWN | 前5日平均の2倍以上の出来高で上昇/下落 |

形状の種類は `pattern_forward_stats.py::DEFINITIONS` と `detect()` を追加して拡張できる。1銘柄のパターン採用後30営業日の制限はそのパターンだけに適用。

## Neon DB設計 — 重複株価ゼロ

`sql/007_pattern_forward_outcomes.sql`:

- `pattern_definition`: パターンの日本語名と判定式の説明（モデルバージョンで固定）。
- `pattern_study_run`: 入力データの期間・学習終了日・検証開始日・実行状態を記録。
- `pattern_forward_stat`: パターン × 学習/検証 × 1～30日後の各行に上昇/下落/横ばい件数、集計対象、観測不能件数、未成熟件数、上昇割合、下落割合、平均騰落率、95% Wilson参考区間。
- `pattern_up_30day`: 画面用の横持ちVIEW。**day01、day02、...、day30列**は上昇割合（％）。保存本体は正規化し、余分な30列×全銘柄の日足複製をしない。
- 全期間で調整後株価約190万行を持つ`daily_bar`は変更しない。インデックスに合った証券コード・取引日順をNeonから**逐次読み込み**、1銘柄ずつ集計。約16パターン×30日×2期間＝960行の集計が基本。

### 横持ち一覧（1行＝パターン）

```sql
SELECT pattern_name, day01,day02,day03,day05,day10,
       day15,day20,day22,day30
FROM pattern_up_30day
WHERE segment='holdout'
ORDER BY pattern_code;
```

### 個別の根拠と件数

```sql
SELECT trading_days_after,signal_events,observed_count,
       up_count,down_count,flat_count,
       missing_count,unmatured_count,up_pct,down_pct,
       avg_return_pct,up_wilson_lower_pct,up_wilson_upper_pct,evidence_status
FROM pattern_forward_stat
WHERE pattern_code='UP3' AND segment='holdout'
ORDER BY trading_days_after;
```

`observed_count`が少ない数字は信頼不能で、100件未満の場合 `INSUFFICIENT_SAMPLE`。上昇割合の95%区間は独立同分布を理想化した標本比率の参考値で、実際には同一市場・相関・時系列依存があるため厳密な予測区間ではない。

## 期間と実行

- 学習：2026年1月30日まで。未来ラベルも2026年1月30日までに確定しているものだけ。
- 検証：2026年2月2日以降。パターンは学習の上昇率を見て自動変更しない。
- 実行：`.github/workflows/pattern-forward-outcomes.yml` をmainへの新規導入時・手動実行時に動かす。Actionsで `DATABASE_URL` を安全なSecretsから読み、Neonの集計テーブルだけ更新。
- データは**GitHub公開リポジトリや公開ログへ出さない**。DB格納は同一実行キーを原子的に再集計する。
- 最新日足が2026年7月17日までなら、2026年7月18日以降の実際の値動きは一切予測値で補完しない。現在の銘柄を購入する際は当日の最新データが別途必要。

## 大切な区別

過去の終値から1～30日後の終値が何%上がったかは、**買い注文が本当に約定できたか**と異なる。
2026年7月17日を終点にした旧バックテストには上場廃止と欠損評価の重大問題があったため、`pattern_up_30day` の上昇比率をそのまま勝率・利益額として購入判断しない。今後、売買停止・上場廃止・全JPXリスク・スリッページ・手数料・指値/逆指値等を組み込んだ**翌営業日実約定を仮定する別検証**が必要。

1銘柄しかない特殊パターンなど標本不足のパターンを自信満々に薦めず、比較対象として `BASE` の基準成績との差も併記する。
