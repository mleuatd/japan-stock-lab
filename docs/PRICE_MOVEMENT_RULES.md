# 騰落率・連続騰落の区分マスター（2026-10-09）

Neon の `japan_stock_lab` に `sql/005_price_movement.sql` を適用しました。

## 設計
- `price_change_band`: 15区分（下落7、変化なし1、上昇7）。`numrange` の下限・上限で分類するので、列増設や株価行ごとの区分保存は不要。
- `price_streak_rule`: 上昇/下落の日数と一日最低変化率を指定する10件の条件マスター。これらは条件定義であり、シグナル結果の永続保存ではない。
- `price_daily_movement`: `daily_bar.adjusted_close` の銘柄別直前観測日に対する騰落率を計算。分割調整後終値が欠損、前回値が0以下なら騰落率は NULL とする。
- `price_daily_streak`: 各銘柄の連続上昇・連続下落・横ばいの日数をビューで計算（非永続）。初回・欠損は unknown として連続日数0。
- 永続的に日足データを複製せず、検索で使う既存インデックスを維持する。

## 実データの動作確認
銘柄コード `54230` の2026-07-16: +0.17%程度、`0～0.5%上昇`、4回連続上昇（保存済みの銘柄別観測日基準）。
翌2026-07-17: -1.24%程度、`1～2%下落`、下落連続1回と判定。
Neonで15区分と10種類のルールの存在、実際のビューの読み取りを検証済み。

## 注意点と次の実装
1. 日次騰落率は**調整後終値**ベース。通常の終値の前日比とは違う場合があります。
2. 「連続営業日」は**その証券コードで価格データが記録された観測日**の連続を指します。売買停止やデータ欠損、上場廃止の影響は検証が必要です。
3. `price_streak_rule` の最低変化率・日数を同時に適用するスクリーニングSQL/画面は、次の作業として残っています。現時点でビューが自動で条件該当銘柄をキャッシュするわけではありません。
4. `price_daily_streak` は全履歴に窓関数を使うので、日次のランキング等と結合して全銘柄を検索すると重くなる可能性があります。銘柄別または期間別に絞り、実測後に必要な範囲だけ高速化します。
5. 騰落率を使った売買判断には損益通算・手数料・出来高不足・ストップ高安等の検証も必要です。マスターの分類結果自体は予測ではありません。

例：
```sql
SELECT trading_date, security_code, pct_change, band_name, direction, consecutive_days
FROM price_daily_streak
WHERE security_code = '54230'
ORDER BY trading_date DESC
LIMIT 20;
```
