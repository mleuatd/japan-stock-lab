# チャート形状から買い候補＋2つの売り条件をセットで比較する（試験実装）

## 使い方と目的

1. 過去日足の形状を5つのルール（押し目、上昇トレンド、上放れ・出来高、反転、出来高急増）で機械判定。
2. 「買った翌営業日の始値」ではなく、**前営業日の終値で条件を判断し翌営業日の始値で仮想買い**。シグナル発生日の当日始値で買ってはいけない。
3. 約定した**買値を基準**に、利益確定の売り指値と損切りの逆指値成行を1組（OCO型）としてシミュレーション。
4. 100株単位、初期現金50万円、1銘柄上限10万円、信用・先物・空売りなし、最大5銘柄。現金不足では買わない。実際の証券注文を生成・送信しない。
5. 売却は最初に当たった条件で1回だけ。両方を同じ日足の高値・安値が跨いだ場合は**必ず損切り優先（悲観側）**。翌日ギャップで損切り水準より下に寄り付いた場合は損切り水準ではなく**低い寄付値**で売却と見なす。
6. 最大保有営業日を超えた場合は翌営業日始値で売却を試み、始値なしの日は売却要求を保持。
7. 期間内の全保有日に始値・高値・安値・終値が記録されていない場合、ポートフォリオ最適化用の確定成績は無効とする。
8. 訓練前半・後半の双方で利益が正で約定3回以上の組み合わせだけ候補にし、テスト期間は最後に1回だけ評価して**再最適化しない**。

## 組み合わせ

- 買付シグナル5種類 × 損切り3/5/8% × 利益確定6/10/15% × 最大保有5/10/20営業日 = **135条件**。
- 単純な「期待利益幅÷損失幅」は勝率ではありません。例えば「損切り-5%、利益確定+10%」は手数料や税金を差し引く前の設定幅が2対1、という意味だけです。
- 訓練結果は期間末に全株を売却したものとしてはいけません。保有中の資産は最終日に終値で時価評価できる場合のみ参考計算。
- 終値があっても企業行動履歴が未検証なら実績・推奨として確定扱いにしません。
- バックテストの売買成立はあくまで**仮想**です。日足から出来高配分、板の順序、寄付注文の約定率、正確な逆指値滑り・制限値幅は復元できません。

## 実行例（私人ローカル環境だけ）

```sh
python chart_bracket.py --root archive/daily --train-to 2026-01-30 --test-from 2026-02-02 --out private-bracket-grid.json
```

日足取得が完全でない場合、何もしない・データ不足と判定するのが正しい場合があります。大規模な全市場×135条件は計算負荷が高く、既存長時間Actionsが終了するまで重複全件実行しません。銘柄別データや実売買元帳のJSONは公開GitHubにコミットしないでください。

## チャート表示

`docs/index.html` に非公開の .csv.gz 日足を端末内で読み込み、`docs/screener.html` を開きます。現在は最大表示数に含まれる銘柄について、当日まで最大22取引日から形状を評価。過去の最終終値から参考注文水準と100株単位の概算株数を表示します。グラフ上の破線と数値は**買値確定後に必ず再計算すべき例示**であって、証券会社の発注画面ではありません。

**データの鮮度**: 現在のJ-Quants無料データには遅延があり、過去のチャート例を「今日買える」「確実に勝てる」と表示しません。日足だけで不明な企業情報、配当、株主優待、店舗の近さは購入根拠一覧の別データとして今後紐付ける必要があります。

## 証券会社の注文方法は同一ではありません

- 証券会社により、IFD/IFD-OCO/OCO/デュアル指値の名称、対応市場、訂正方式・注文期間が異なります。
- 実際の買い注文と利益確定・損切り注文を一括予約できるかは、その証券会社の個別条件に従ってください。
- 売り注文の数量は実際に保有する株数以内でなければなりません。買付約定前に手動で独立した現物売り注文を出す処理は実装しません。
- 参考: [大和証券 条件付注文](https://www.daiwa.jp/products/equity/stc/rvs/)、[SBI証券 IFD/OCO/IFDOCO](https://faq.sbisec.co.jp/answer/5ed768ec878c430011c176b1/)

**ステータス**: BACKTEST_PROVISIONAL_ONLY — 実証済みの勝率、最適購入条件、将来の収益を保証しません。
