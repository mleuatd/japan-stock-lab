# 保有中の状態から「なぜ売るか」を積み上げる説明可能な検証

## 以前の方式と変更点

従来は損切り幅・利確幅を23個先に決めて試していました。新設した `conditional_exit_discovery.py` は日々の実際のチャート状態を記録し、同一の過去銘柄・同一取得日について「その日の終値から翌営業日の寄り付きで売る」場合と「30営業日目の寄り付きまで保有する」場合を比較します。結果がよかった説明条件だけを組み合わせます。

## 事前に定めた6系統・20個の説明可能な状態

1. 保有期間：1～5日、6～15日、16～28日
2. 含み損益：-5%以下、-5～-2%、-2～0%、0～+2%、+2～+5%、+5%以上
3. 保有中の最高終値からの下落：5%以上、2～5%、2%未満
4. 過去3営業日の上昇率・下落率の方向と幅
5. 2営業日または3営業日連続の前日比下落
6. 5日平均終値が20日平均を下回るか

ただの閾値総当たりと異なり、各条件が過去にどんな状況と結びついていたかを記録します。運用判断には当日終値までの情報のみ利用し、執行は翌営業日始値とするため、架空の損切り約定を仮定しません。

## 発見・積み上げの順序

- 最も古い学習期間 `TRAIN_A` の全条件有効チャート `ALL` のみで単一状態の改善を評価。数値の基準は事前固定。以前作成した `SURVIVOR` フィルタはその後の学習期間 `TRAIN_B` の情報を使っているため、古い `TRAIN_A` でのルール発見には使わない（未来情報漏洩防止）。
- 「損失だった保有を回避した件数」と「逆に新しく損失になった件数」を区別し、5%以上の損失悪化なら採用候補から排除。平均利益の犠牲も併記。
- 有望な上位4つの状態について、それとは別の説明系統を1つ追加したAND条件を検証します。これ以上複雑な条件を際限なく増やしません。
- `TRAIN_A` で一番の候補を固定した後、`TRAIN_B` で再現を評価。`HOLDOUT` は説明用に結果を出すのみで、候補の変更には使用しません。
- `HOLDOUT` は前の実験で一度調べているため真の新規データではありません。買い推奨・利益保証はしません。

## Neonに記録する根拠

- `conditional_exit_run`：研究の出典、日時、選ばれたルール、再現状況
- `conditional_exit_effect`：1条件・2条件の売却ルールと30営業日保有の正確な一対一差
- `conditional_exit_day`：保有1～28日目のそれぞれの状態で、その後に損失となった比率、売却によって防いだ損失と新たに生じた損失の件数
- `conditional_exit_reasoned_effect`, `conditional_exit_daily_causes`：比較しやすい集計ビュー

**注意**：これは相関・歴史的売買シミュレーションの説明であり、因果関係の証明ではありません。同じポジションの異なる日を独立した売買サンプルとして合算しない設計です。株式分割等の監査済み銘柄を対象とし、検証不能な12銘柄は除外。上場廃止・TOB・税金・端株など未対応で、研究専用 `NOT_APPROVED` です。これまでの購入パターン群は「損失ゼロ」を再現できていないため、新しい出口ルールの成績が改善しても直ちに実売買には使いません。
